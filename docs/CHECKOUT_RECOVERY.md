## Checkout UX and recovery

Wallet connect and message signing have a 90-second UI timeout; HTTP calls have a 45-second timeout. Transaction sending intentionally has no artificial timeout because a late broadcast could still occur. Each phase has distinct status text. The order is persisted before sending; failure to persist blocks payment. Once a signature is saved, pending verification polls every five seconds up to twelve attempts while checkout is mounted. Manual retry resets the polling budget. No automatic payment resubmission. A rejected or ambiguous order is retained for manual recovery; a missing signature still requires the user to recover it from wallet history. Backend remains the sole entitlement authority. Local browser storage is account scoped but not a durable multi-device order ledger; server reconciliation remains future work.
